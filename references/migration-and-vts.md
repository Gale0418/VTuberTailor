# 專案遷移、可攜性與 VTS

## 搬移舊專案

先依使用者指定的保留範圍，複製並驗證必要原始碼、素材、canonical 專案及成品。若使用者要求完整歷史備份，必須取得已驗證的封存收據；未完成的 ZIP 不算備份。使用者明確允許捨棄可重建依賴或舊試作品時，記錄範圍，不把完整封存另設成批准門檻。

封存／搬移舊工具或工作目錄後，必須以新倉庫的包裝入口完成可攜性驗收；不能只靠舊路徑仍存在時測試成功。先在倉庫根目錄執行 `setup`、`doctor`，再依各命令的 `--help` 確認選項，檢查引擎、素材、reference、輸出與工具解析都指向預期的新根目錄。對既有專案做只讀 `inspect`／驗證，確認絕對舊路徑沒有被當作必要依賴；必要時以新根目錄做副本遷移，保留原始素材與可回復點。僅在新路徑驗證通過後，才刪除已獲授權清理的舊位置。

驗收結果須記錄實際使用的根目錄、命令、專案識別／revision、發現的外部依賴與剩餘絕對路徑。相對路徑應以專案或倉庫根目錄解析；工具快取、已安裝應用或使用者設定可留在其正常機器位置，但不得混成專案必備內容。不要硬編碼某位使用者的磁碟、家目錄或專案路徑。

## VTS 交付

依 `package-vts --help` 製作套件，並用 `smoke --help` 確認相應檢查。先記錄現有 VTS 使用設定，交付期間保留設定；使用該使用者指定的啟動器與安裝慣例。不要覆寫無關模型、全域追蹤／攝影機設定或使用者配置。若出現 VTS 授權或安全提示，停在提示處，遵從應用自身的安全流程；不得嘗試自動點選、繞過或壓制提示。

交付檢查至少確認套件檔案、模型引用、載入結果及設定保留狀況。VTS 已載入的日誌／截圖只能證明其記錄範圍內的事實；沒有實機可見畫面時，外觀、追蹤混合、待機和實機效能均標為未驗收。離線 Core 渲染圖及預覽 FPS 不可當作 VTS 實機證據。Editor 尚未另存也須分開標示。
